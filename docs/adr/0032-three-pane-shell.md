# ADR 0032：三栏外壳——左栏工作区、中栏现场、右栏运行详情

- **状态：** 已接受（Accepted）
- **日期：** 2026-11-28
- **相关：** ADR 0029（导航拓扑、注意力口径）、ADR 0019 / 0030（视觉层）、ADR 0022（对话优先）；`docs/UI-SPEC.md` §4；`docs/PLAN-CONSOLE-INTERACTION.md`
- **证据：** `packages/web/src/app/AppLayout.tsx`、`Sidebar.tsx`、`InspectorPanel.tsx`、`features/settings/SettingsDialog.tsx`；渲染核对 1440 / 768 / 390（明暗两套），axe 无 critical/serious

---

## 1. 背景

ADR 0029 把导航收敛成「对话 / Agent + 设置」两个目的地，会话历史进左侧抽屉，注意力进顶栏胶囊，运行详情是整页（`/tasks/:id`）。落地后发现三处摩擦：

1. **“我在哪儿干活”被拆成两处。**顶栏说目的地，抽屉说会话；换一条会话要多一次“打开抽屉”，而这个动作是最高频的。
2. **看运行详情会丢掉对话。**判断（对话里的证据、审批、澄清）与证据（运行报告）被放在两个页面，来回切换时上下文重建。
3. **设置是页面。**改完主题/模型要再走一遍导航回到刚才的对话；而 Agent 接入（catalog 扫描与授权）本该是配置，却和现场并列成第二个分段。

## 2. 决策

**外壳改成三栏，取消顶栏。**

```text
┌──────────── 268px ────────────┬──────── 中栏（flex）────────┬─── 右栏 320–760 ───┐
│ 品牌                           │ 页面头（h1 + 一个开关）      │ 运行详情（h2）      │
│ ＋ 创建新工作区                 │                             │ 判决 + 证据 + 审批  │
│ Agent 活动大屏幕 / 等你处理 N    │ 对话 / 任务索引 / 现场        │ 或文件内容          │
│ 工作区（按目录分组）            │                             │                     │
│ 设置（底部）                    │ 输入壳                       │                     │
└───────────────────────────────┴─────────────────────────────┴─────────────────────┘
```

- **左栏是常驻的**：新建工作区、Agent 活动大屏、注意力（无待办时不出现）、按目录分组的会话、底部的连接状态与设置。会话行的重命名 / 归档 / 删除留在行菜单里，不在别处再放一套。
- **中栏是唯一的一级标题来源**（`h1`）：对话标题、任务索引标题、Agent 活动标题各归各页。
- **右栏是观察面，不是目的地**：运行详情（`TaskDetailView`）在这里展开，标题是 `h2`；对话不因看证据而卸载。宽度可拖，320–760px，记住上次的值。
- **运行不是页面**：`/tasks/:id` 仍然可深链，它做的是「中栏切到这次运行所属的对话 + 右栏打开这次运行」。没有来源会话时中栏退回索引，右栏照样可看。
- **设置是弹框**：`/settings`、`/settings/:section` 可深链；左菜单（通用 / 模型 / Agent 接入）+ 右内容，关掉回到对话。
- **Agent 接入进设置**，与现场不再并列；`/registry` 保留为 replace 跳转到 `/settings/agents`，书签不失效。
- **窄屏**：≤960px 左栏收成抽屉（带召回按钮与 Esc），右栏改为盖住中栏的全宽面板；≤860px 的正文量度不变（720 居中）。

维持不变的口径：注意力仍只有 `shared/attention` 一个派生源，仍不占导航位、没有待办时不出现；运行仍是对象而不是地点；对话仍是唯一的人类建任务入口（ADR 0029 §2.1）。

## 3. 被否方案

- **保留顶栏 + 抽屉，只改配色。** 换会话的两次操作没有消失，只是变好看了。
- **运行详情继续做整页，只在对话里放一个“打开”链接。** 这正是第 1 节第 2 条摩擦本身。
- **设置做成整页（现在的做法）。** 改一个开关就丢失对话现场；把它做成弹框，关闭即回到刚才的位置。
- **把 Agent 接入做成第三个导航目的地。** 它一年用几次，却是“配置”而不是“干活的地方”，占导航位就是把低频动作放在高频路径上。
- **左栏做成可收起的 56px 图标 rail（ADR 0029 §6.4 曾否掉的形态）。** 这次不需要：左栏的内容是**会话名**，图标表达不了；收起状态只能记住目录，反而增加一次点击。

## 4. 后果

**正面**

- 换会话、看运行、改设置各自少一次跳转；判断与证据并排，不再重建上下文。
- 左栏把“当前在哪个工作区”变成常态可见，而不再靠中栏副行的一行小字。

**负面 / 必须承担**

- 1440px 下常驻左栏占 268px；中栏的可读量度靠 720px 居中兜住，不随窗口变宽而变差。
- 1100px 以下右栏会盖住中栏，看完要显式关闭（有 `Close details`，Esc 不劫持对话输入）。
- 会话一多（经验上 >200 条或需要跨目录检索），左栏会需要分组折叠或虚拟列表；现在的搜索只过滤标题与最后一条消息。
- 两处渲染同一份会话摘要（全局 store + 侧栏），靠 `writeCachedSummaries` 保持同源；新增入口必须走 `app.refreshThreads()`，不要各自再写一份。

## 5. 复审触发条件

- 左栏会话常态 >200 条，或需要按仓库/标签分组、批量操作。
- 右栏容纳不下一次运行报告（证据链变长到需要独立页面）。
- 手机端出现“需要常驻导航”的真实诉求（现在的抽屉是召回式）。
- 出现“设置必须与对话同时长驻”的操作（例如批量改模型并对照运行）。
