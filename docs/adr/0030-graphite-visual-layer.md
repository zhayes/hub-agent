# ADR 0030：视觉层换成 Graphite，颜色只留给「判决」与「需要你」

- **状态：** 已接受（Accepted）
- **日期：** 2026-11-27
- **相关：** ADR 0019（UI 依赖白名单）、ADR 0029（注意力优先的控制台）、`docs/UI-SPEC.md` §2、`docs/PLAN-CONSOLE-INTERACTION.md` §3.3 / §6 P2
- **证据：** `packages/web/src/styles/tokens.css`（令牌唯一来源）、`packages/web/src/styles/tailwind.css`（语义映射）、`docs/design/comps/v2.css`（设计期稿，不入库）

---

## 1. 背景

Warm Ink（暖纸 + 橙 accent）是 v2 迁移期的视觉层。它在两处失效：

1. **accent 同时表示“主操作”和“运行中”**：一个颜色两种含义，用户无法靠颜色判断“是不是轮到我了”。这一冲突在 UI-SPEC §2 里被标为已知问题，一直没有收口。
2. **暖底与 diff 的红绿争艳**：代码证据是控制台的主要内容之一，暖纸让 `+18 / -6` 的红绿看起来更脏。

同时，对话页重设计（v2–v9 设计轮）已经把“颜色只出现在判决与「需要你」”当成结构前提；如果令牌层不跟上，稿子与实现会长期分叉。

## 2. 决策

**换 Graphite：chrome 全灰阶；颜色只出现在两处。**

1. **判决**：`--success`（通过）/ `--danger`（未通过）。
2. **需要你**：`--accent`（= signal，琥珀）。运行中不再用琥珀。

规则随之变化：

- **主按钮用 `--fg-default` 实底墨色**，不用 accent。动作的强调来自尺寸与位置，不借“需要你”的颜色。
- **焦点环与 signal 同源**（琥珀），因为它同样是“这里要你看”。
- 令牌语义名不变（`bg-canvas` / `fg-muted` / `line-*` …），只换值；`--accent` 的**用途**被收窄。
- 动效曲线进令牌层（`--hx-ease-*` / `--hx-dur-*`），因为它和颜色一样是跨组件的共同语言。

对比度实测（WCAG，两套模式分别取最差）：

| 角色 | Light | Dark | 对比 |
|---|---|---|---|
| fg / fg-muted / fg-subtle | `#12151A` / `#545B65` / `#636B78` | `#E6E8EB` / `#A8AEB6` / `#7C848E` | 17.1·6.4·5.02 / 15.9·8.75·5.17 |
| signal（= 待你处理） | `#8A5A00` | `#F5A524` | 5.53 / 9.59 |
| pass | `#1A7F37` | `#3FB950` | ≥4.5 |
| fail | `#B3261E` | `#F85149` | ≥4.5 |

初版三个 `fg-subtle` 候选值实测 4.25 / 3.79 / 3.25 全部不过线，已重取（见 PLAN §3.3）。

圆角同时收口为三档：**控件 6 / 卡片 12 / 输入壳 16**。同屏三种以上圆角是未收口信号。

## 3. 被否的方案

| 方案 | 否决原因 |
|---|---|
| 保留 Warm Ink，仅把 accent 拆成两个颜色 | 暖底与 diff 红绿争艳的问题没解；且“暖纸”气质与“调度台”的产品定位本就相左 |
| 全灰阶 + 无数色（通过/失败也用灰） | 判决是产品最核心的信息，去掉颜色等于让用户逐字读；违反“完成后能判断该不该信”（US-007/008） |
| 引入第二套设计系统/组件库来换肤 | ADR 0019 白名单不变；换肤必须靠令牌，不靠换库 |
| 直接把设计稿的 CSS 搬进产品 | 稿子不处理焦点、暗色系统的 `light-dark()`、减动效与 a11y；只搬“值”，不搬“结构” |

## 4. 代价

- 放弃暖纸气质，换来与 diff、图表不争艳的中性 chrome；产品的“温润感”消失，这是**刻意的**。
- 所有视觉基线（`tests/visual/**`）需要重做一次——它们记的是 Warm Ink 的像素。
- `--accent` 语义收窄后，任何“用 accent 表示运行中”的旧代码都会变成误用；本轮已把 `StatusBadge` 的 running 改成中性。

## 5. 复审触发条件

- 用户反馈“看不出哪里在跑”（中性 running 的可辨识度不足）——考虑给运行中加**动效**而不是颜色。
- 引入图表/统计页（PRD §9.2 的 P1 成本统计）导致灰阶层级不够用。
- 需要无障碍强化模式（高对比 / 色盲友好）——届时判决色改用形状 + 符号，不只换色。
