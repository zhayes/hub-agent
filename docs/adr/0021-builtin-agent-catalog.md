# ADR 0021：内置 Agent 目录 —— 只记录"怎么启动"，不参与"怎么理解协议"

- **状态：** 已接受（Accepted）
- **日期：** 2026-11-26
- **相关：** `docs/PLAN-AGENT-ONBOARDING.md`、`docs/PRD.md` §6.3.5 / §18.9、ADR 0005（ACP 官方 SDK）、ADR 0020（3D-only 舞台）

---

## 1. 背景

接入页需要"扫描本机有哪些可接入的 Agent"。现实是：操作系统没有"已安装 ACP Agent"注册表，能不能走 ACP 只取决于具体启动参数——DSH 需要 `--profile acp`，Hermes 是 `hermes-acp`，WorkBuddy 需要 `ELECTRON_RUN_AS_NODE=1` 加内置 CLI，Codex / Claude Code 还需要额外的 ACP 适配器。

如果把这些知识写进代码分支（`if (name === 'dsh') …`），就和 PRD §18.9 正面冲突：

> 不做 per-harness 特判、不做版本嗅探、不维护"版本绑定表"。

但反过来，如果完全不内置任何启动知识，用户就必须自己拼一条长命令——实测里这条路的错误率极高（相对路径、引号、缺环境变量、缺适配器），且失败信息往往只有一句"进程已退出"。

## 2. 决策

引入一个**声明式的内置目录**（包内数据文件 `catalog/builtin.json`），只回答一个问题：**某个 harness 怎么以 ACP 模式启动。**

### 2.1 允许与禁止

| 允许（启动知识） | 禁止（协议特判） |
|---|---|
| 记录启动命令的 argv / flags / env | 按 harness 名改变协议解析 |
| 检测文件是否存在、多平台路径差异 | 用版本号决定行为、维护版本兼容矩阵 |
| 记录 asar 内的虚拟路径（`virtualCli`） | 读取或解析 asar 内容 |
| 读取并**展示** `--version` | 把版本号写进任何分支判断 |
| 提示"缺少 ACP 适配器" | 自动安装、自动下载、给出安装命令 |
| 声明无窗口（headless）启动方式 | 启动 GUI 窗口或依赖用户界面 |

一句话：**目录只决定"怎么启动"，绝不参与"怎么理解协议"**。能力差异仍然只通过 ACP 的 capability 协商暴露（ADR 0005）。

### 2.2 硬约束

1. **`headless: true` 才能收录**：命令必须无需窗口即可运行（如 `ELECTRON_RUN_AS_NODE=1`）；含 `open` / `start` / 直接拉起 `.app` 的条目一律拒绝。
2. **扫描不执行二进制**：只做文件存在 / PATH 检测，不跑 `--version`。实测 WorkBuddy 的 `--version` 会下载 62 MB 插件市场——扫描必须是零副作用的。
3. **收录需实测**：条目必须在本机跑通 ACP `initialize` 才能进内置清单，记录 `verifiedAt` 与验证时的版本。
4. **不自动探测**：空闲 Agent 不做轮询；验证只发生在接入或用户手动触发时。
5. **登录只发生在接入阶段**：任务执行期禁止弹窗（浏览器 / 终端 / 设备码）。`terminal` 类型的登录方式不支持。

## 3. 后果

- 目录成为**随版本发布的数据文件**，新 Agent 支持通过发版提供，不做远程下发（local-first，避免供应链风险）。
- 目录会**过期**：应用升级换了路径、适配器改名。因此接入时必须持久化 `catalog_id` / `variant_id`，重新扫描时能提示"命令已失效，重新解析"。
- 新增 Agent 支持的流程变成：加一条条目 + 本机实测 + 写进目录，不需要改 Runtime、Brain 或协议层。
- 目录之外的 harness 不在页面上提供自由输入框（PRD §6.3.5 的"来源不明命令"约束）；CLI 的 `agent add` 保留为脚本与排障入口。

## 4. 被否掉的选项

| 选项 | 否决原因 |
|---|---|
| 代码里按 harness 名写分支 | 就是 PRD §18.9 明令禁止的 per-harness 特判 |
| 不做目录，全靠用户手填命令 | 错误率高、失败不可诊断，且与"打开页面就能接入"的目标冲突 |
| 扫描时逐个启动验证连通性 | 副作用大（进程、网络、磁盘）、慢；且会踩"自动执行来源不明命令"的红线 |
| 远程下发目录（启动时拉取） | 违背 local-first，引入供应链与隐私风险 |
| 自动安装适配器/CLI | 直接违反 §18.9 的"不得自动安装、不引导下载" |

## 5. 复审触发条件

- 出现第三种"必须改协议行为才能接入"的 harness（说明标准 ACP 不覆盖真实需求）。
- 目录条目超过 15 条，或同一 harness 需要维护多套版本相关命令（说明目录正在变成版本绑定表）。
- ACP 官方提供机器可读的 agent registry（届时评估是否取代内置目录）。
