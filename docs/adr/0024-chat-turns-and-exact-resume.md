# ADR 0024：对话回合视图与精确续跑

状态：Accepted（2026-11-26）

## 背景

对话页把过程、任务、授权、回答渲染成各自带身份的消息，读起来像多个角色；右侧栏只能看摘要；审批后 `resume` 会把最后一条用户消息当新目标重跑，澄清后也会重新分解计划。用户要求：思考收进回合头、产物挂在回合下、右栏能读任务和文件、审批/澄清续跑不要重来。

## 决定

1. **回合是前端派生视图**，不新增 `turns` 表：按 user 消息切分，steps（过程/卡片）+ final（回答）+ artifacts（任务/文件）。旧历史零迁移。
2. **右侧栏是只读阅读器**：任务复用任务证据查询；文件走 `GET /tasks/:id/file`，限定改动文件、worktree/project 根、路径与大小防护，不提供编辑。
3. **审批续跑同一 execution**：`execution_resume` 保存 worktree + checks；`resumeExecution` 只重放验收（放宽写范围），不重跑 Agent；工作区回收则拒绝并提示重新执行。
4. **澄清续跑同一 Task**：`continueWaitingTask` 只对 waiting_input 子任务开新 attempt，不新建 Goal、不重新分解。
5. **流式协议**：聊天回合允许自然语言直出并逐字流式；工具动作用 meta-tool。JSON 输出走回退，且不把 JSON 流到界面。

## 被否方案

- 给消息加 `turn_id` 并迁移：需要回填历史，收益仅是少算一次分组。
- 审批后重跑 Agent：会丢失现场，且 Agent 已完成的改动要重做。
- 文件预览支持编辑：越权与并发写风险，不符合“本地优先 + 只读证据”的边界。

## 后果

- 完成态回合默认折叠，过程信息不干扰阅读；运行/失败/等待时自动展开。
- 文件预览受 worktree 生命周期限制；回收后只能看任务页。
- 沙箱放宽仅覆盖写路径；网络类拒绝需要后续策略实体。
