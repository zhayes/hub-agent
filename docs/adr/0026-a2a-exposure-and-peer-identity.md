# ADR 0026：A2A 暴露面与 Peer 身份

状态：Accepted（2026-11-26）

## 背景

`AGENTS.md` 写死「本地服务只监听回环地址」，而跨机器 A2A 是项目必做能力（PRD Phase 2 / V1.1）。`PLAN-A2A.md` §6 提出“A2A Server 作为独立受控监听面”，但没有把部署形态、身份机制与撤销路径定下来，导致实现无从下手，也容易顺手复用本机 Web Console 的 bearer token。

## 决定

**暴露面**

- A2A Server 与本地 HTTP API 是**两个面**：本地 API 继续 `127.0.0.1` + token；A2A Server 是独立端口，**默认关闭**，需显式配置启用。
- 这是对「只监听回环」的唯一例外，且仅限 A2A Server。启用非回环监听必须由用户显式操作（配置项 + 启动时日志明示）。
- TLS 由 A2A Server 自己终止。走 Relay 时 Relay 只做连接路由与信封转发，**不终止 A2A 语义层**，任务真相仍在两端 SQLite。

**Peer 身份**

- 首次配对是一次**用户可验证的操作**：对端出示一次性配对码，本机确认后交换长期公钥。
- 之后 Peer 之间用 **mTLS** 承载请求；Agent Card 用 JWS 签名，客户端校验签名与公钥一致。
- **不复用** Web Console 的 bearer token，也不把 Agent Card 声明当作授权凭证（PRD §7.2 已写明能力声明不代表质量/授权）。

**授权与撤销**

- 授权是**本地方向性**的：每个 Peer 独立配置可访问能力白名单、预算上限、速率与并发上限。
- 撤销、轮换、配额变更全部在本地生效，不依赖对端配合；进站请求在**创建任务之前**被拒，保证零副作用。
- 审计记录包含 peerId、请求摘要与拒绝原因，但不落 token/密钥原文。

## 被否方案

- **复用本地 token 做跨机认证**：token 是给本机控制台用的文件凭据，无法表达“是哪个 Peer”，也无法独立撤销。
- **只走 Relay、不做直连**：把 Relay 变成事实上唯一的信任锚点，违反“Relay 不是任务真相源”，也给单点故障背书。
- **公网直接暴露、靠 Agent Card 做认证**：Agent Card 是公开描述文档，任何人可读，不具备认证意义。
- **首版上 OAuth/OIDC**：需要引入授权服务器与用户体系，超出本地优先产品的范围；mTLS + 配对码足够覆盖“开发者之间互信”。

## 后果

- 需要在 `interfaces/a2a` 做独立的路由与鉴权中间件，不复用 `interfaces/http` 的 token 中间件。
- 需要 Peer 存储（公钥、能力白名单、预算、撤销状态）与迁移。
- `AGENTS.md` 的「只监听回环」需注明这一唯一例外及其成立条件。
- Relay 的安全边界（信封加密、路由授权、重放保护）单独验收，不在本 ADR 内。

## 复审 / 变更（2026-11-26）

**变更：** A2 阶段不实现 mTLS。原因：可用 SDK（ADR 0028）接入阶段先把协议、映射与鉴权跑通，mTLS 需要证书签发/轮换/信任分发，成本会掩住“能不能委托”这个真问题。

A2 阶段的做法：

- 仍要求 TLS（自签或受信反向代理终止），不允许明文跨机；
- Peer 认证用**配对码派生的一次性 bearer token** + 请求签名，按 peerId 独立撤销与轮换；
- token 短 TTL + 本地撤销表，重放窗口靠 TLS + TTL 控制。

**遗留风险（必须在 A4 之前消除）：** bearer token 只能证明“拥有 token”，不绑定传输层身份；在经 Relay 转发、或监听面暴露到更广网络时，这个强度不够。因此：

> 启用 Relay 之前，必须把 mTLS（或等价的双向身份绑定）落地，并补充本 ADR 的“变更”记录。

原结论中的其它部分（独立端口、默认关闭、配对码、本地方向性撤销、Agent Card 不等于授权）不变。

## 复审 / 变更（2026-11-27）：mTLS 前置已落地

**变更：** 上面那条“A4 之前必须消除”的遗留风险已消除——A2A 监听面现在能承载双向 TLS，且身份来自客户端证书。

已实现（有测试）：

- **TLS 由 A2A Server 自己终止**：`startA2aServer({ tls })` 用 `node:https` 监听（必须显式传 `createServer`，否则 `@hono/node-server` 会退回明文监听），Agent Card 的 URL 自动改用 `https://`。
- **非回环监听强制 TLS**：`host` 不是回环地址且未配置 `tls` 时**拒绝启动**（`CONFIG_INVALID`）。宁可起不来，也不要明文暴露。
- **mTLS 身份 = 客户端证书**：`requireClientCert: true` 时 `requestCert + rejectUnauthorized`，证书链由 Node 在握手阶段校验（不受信 CA 直接握手失败）；应用层再把证书指纹映射到 peerId，未注册/已撤销 → 401，零副作用。
- **不降级**：mTLS 模式下**忽略** `Authorization`，不存在“有合法 token 就能绕过证书要求”的路径。
- **指纹绑定统一进 peer 模型**：`a2a_peers.cert_fingerprint`（仅 DER 的 sha256，不存证书/私钥），部分唯一索引，支持本地撤销（撤销立即生效）。
- **出站也支持 mTLS**：`connectRemoteAgent({ tls })` 用 `node:https` 实现的 fetch 携带客户端证书（全局 fetch 无法带证书，而项目不引 undici）；Agent Card 拉取与 JSON-RPC 走同一条通道。

不在本次范围（仍是后续工作）：

- 证书**签发/轮换/分发**的用户流程（配对码换证、到期提醒）尚未做；当前由配置注入 PEM。
- Relay 的 TLS 终止点、信封加密与路由授权（A4 本体）未做；本变更只保证“监听面能要求 mTLS、身份可绑定可撤销”。
- 未引入 OCSP/CRL：撤销以本地 `a2a_peers.status` 为准，符合“撤销不依赖对端配合”。

## 复审触发条件

- 出现“组织内多租户 / 需要 SSO”的真实需求；
- Relay 被要求承担任何任务状态职责；
- 配对码方案被证明易被钓鱼（需要更强的带外验证）。
