# ADR 0033：工作纸表面语言——零线条、色阶分区、三栏就地折叠

- **状态：** 已接受（设计定稿；代码待落地）
- **日期：** 2026-11-28
- **相关：** ADR 0029（注意力口径）、ADR 0030（Graphite 令牌）、ADR 0032（三栏外壳；其 §3 被否的「56px 图标 rail」由本 ADR 改判）、ADR 0004（UI SDK 行为层）；`docs/UI-SPEC.md` §12；`docs/PLAN-CONSOLE-INTERACTION.md` §3.8
- **证据：** 设计稿 `docs/design/comps/proposal.html`（P1–P5 五轮对照，产物不入库）；落地后以 1440 / 768 / 390 明暗两套 + axe 复核

---

## 1. 背景

ADR 0032 把外壳收敛成三栏，分区的表达方式是**色阶 + 1px 线**：左栏与右栏各画一道边界线，页头画一道下划线。落地后连看几版，问题集中在同一处：

1. **框太多。** 1440 宽下有 3 条竖向边界 + 2 条页头下划线；每一道都在把画面切碎，而这三栏本来就是同一张工作台。
2. **线在动的地方更刺眼。** 折叠/展开时要连带处理线的起止，`::after` 的渐变要跟着重新定位，状态越多越难对齐。
3. **右侧区的"浅一档"与主题不协调。** 卡片用 `bg-subtle` 铺底后，在浅色主题下白底与灰块相间，像贴了一堆便利贴。

设计侧因此做了五轮对照（详见 §3 被否方案），结论是：**只留一种表面，靠色阶和不移动的纸来分区，一条线都不画。**

## 2. 决策

**整窗是一张圆角纸（`--radius-shell`），纸外只露 8px 桌面；三栏是纸内的三个色阶区，不使用任何 1px 分栏线。**

### 2.1 色阶阶梯（替代 0032 的"线 + 面色"）

自暗到亮是一条单调阶梯，相邻两档必须可分辨但不必高对比：

```text
desk（纸外 8px，最暗）  <  zone（左栏 / 右栏 / 设置导航）  <  surface（纸面：对话 / 设置内容）
                                                          ↑ 纸上静块用 subtle、输入壳用 control-surface
```

- `desk` 与 `zone` 是新增两档；`surface` 从"卡片"升格为"纸面"（0032 里对话区用的是 `canvas`）。
- `zone` 与 `subtle` 在浅色主题下可以同值：它们永远不相邻（`zone` 是栏底，`subtle` 只出现在纸面上），所以不取消"层与层必须有差值"这条老规矩，而是把它限定为**相邻层**。
- 输入壳是唯一允许带 1px 环的静置元素（表单控件的可感知边界，WCAG 1.4.11），环用 `--control-ring`，不是 `--line-*`。

### 2.2 分区与滚动边界

- **不画分隔线**：栏与栏之间不画线，页头不画下划线，卡片不描边。
- **滚动边界用 mask 淡出**（14–18px），内容在页头/输入面下"化开"，而不是被一条线切断。
- 层级顺序：`zone` 的栏底不因滚动改变浓度；纸不随内容滚动。

### 2.3 三栏就地折叠（修订 0032 §3 的"否掉 56px 图标 rail"）

- 左栏 264 ↔ 56（图标条），右栏 420 ↔ 0。
- **纸不移动、不加遮罩、不做抽屉**：容器 `width 200ms`，栏内内容 `opacity 90–110ms` 先淡出，行宽固定（`calc(var(--rail) - 16px)`）所以文字不重排，只被裁掉。
- 窄屏（≤960px）的抽屉行为**不变**，仍按 ADR 0032；本节的折叠是桌面宽度下的手动能力，不是窄屏兜底。
- 右栏展开恢复上次宽度；0032 的拖拽（320–760）保留，收起只是把宽度归零。

0032 当时否掉的三个理由，逐条重估：

| 0032 的理由 | 现在为什么不成立 / 可以接受 |
|---|---|
| 左栏内容是会话名，图标表达不了 | 收起后**会话名仍在中栏页头**可见；收起是用户主动选择，不是默认态 |
| 收起后只能记住目录，反而多一次点击 | 收起的主要收益是**中栏多出约 208px 阅读宽度**（长对话、代码块、diff），这比"少一次点击"更值钱 |
| 与窄屏抽屉是两套机制 | 两者触发条件不同（手动 vs 断点），共用同一套宽度过渡与内容淡出 |

### 2.4 面板极简

- **右栏没有页头、没有关闭图标**：内容从面包屑直接开始。开关只有页头右侧一个面板图标（`aria-pressed`）。
- **左栏脚注只留设置图标**（齿轮），不带文字。
- **注意力只用一个点**：需要审核的会话在标题前放 6px 点，不设"等你处理"导航项——注意力已经在列表里，再放一个导航位就是把同一件事说两遍。
- **审核判决用图标**：实心 ink 圆 + ✓ = 批准，描边 ✕ = 拒绝；两者都必须有 `aria-label` 与 tooltip。

### 2.5 设置弹框

左导航（196）+ 右内容，内容**上下布局**（图标 + 标题在上，控件在下），不再用"左标签列 + 右控件列"——窄内容会让说明文字换行。右上角关闭，**底部不放"完成"**（改动即时生效，关闭即离开）。

### 2.6 输入壳的控件行

- 权限是**可点触发器**（盾图标 + 文案 + chevron），不是说明文字；
- **限制可用 Agent 只给一个漏斗图标**，点开是另一层弹框，本层不展开；
- 两者都在 22px 高、11px 字、`--fg-subtle`，hover 出 `--bg-hover`。

## 3. 被否方案

- **P2 / P4：两头淡出的 1px 刻度线。** 比满高硬线柔和，但仍然是"线"，折叠时要跟着重新定位，且没有解决"框太多"。
- **P3：半透明材料 + blur。** 需要内容在面板下方真实滚动才成立；与 §2.2 的"禁止玻璃"冲突（ADR 0030 §2.2），且 `prefers-reduced-transparency` 下要另做一套退路。
- **保留 0032 的常驻不可收左栏。** 见 §2.3 的重估。
- **把右栏继续做成覆盖式中栏的面板。** 观察面会遮住判断现场，与 0032 §1 第 2 条摩擦同类。

## 4. 后果

**正面**

- 画面只剩一张纸，注意力回到内容；折叠时没有线要维护，状态组合从"线 × 宽度"降为"宽度"。
- 两侧可收使 1440 下的中栏可以从 812 增到约 1080（双收），长内容不必横向滚动。
- 设置页的上下布局对长文案免疫，中英切换不换行。

**负面 / 必须承担**

- 少了两条线，**分区的可辨识度完全依赖色阶**：低质量屏或强环境光下 `zone` 与 `surface` 可能糊在一起。落地时必须在 `scripts/contrast.mjs` 的配对表里补 `fg-* × bg-zone`、`fg-* × bg-desk` 两组，不能只靠肉眼。
- 纸外的 8px 桌面在 ≤1280 的窗口里显得局促（可接受：它只是衬边，不承载内容）。
- 折叠是新增状态，`prefers-reduced-motion` 下要保证"瞬间切换 + 内容不闪"（宽度不做过渡，透明度也不做）。

## 5. 复审触发条件

- 折叠后"换会话"成为高频抱怨 → 重新评估是否给图标条补一个会话入口（P5 明确不做）。
- `zone` 与 `surface` 在实测屏幕上分不出来 → 拉开两档，或恢复"只画在栏内、非满高"的刻度线（P2 形态）。
- 出现第四个栏/区域 → 先问它是否属于纸内，而不是再加一档色阶。
