## 0. 一句话结论

现在的控制台是**状态陈列柜**：五个平级目的地，判据是"系统有哪些实体"，而用户真正的任务是三件事——**说一句要干什么**、**该我出手时立刻知道**、**完成后能判断该不该信**。

重构后的外壳（ADR 0029 已定）：

> **2026-11-28 变更（ADR 0032）：**本节的“2 个目的地 + 设置、会话进抽屉、注意力进顶栏”已被三栏外壳取代——左栏常驻（工作区/会话/设置）、无顶栏、运行详情进右栏、Agent 接入并入设置弹框。下文的注意力口径、运行是对象、单主操作三条不变；凡与外壳拓扑有关的段落以 ADR 0032 为准。

- 导航从 5 个目的地收敛到 **2 个 + 设置**：`对话 · Agent · 设置`；
- **运行是对象，不是地点**：`/tasks/:id` 保留可深链，但不占导航位；
- 需要人处理的事收敛为**常驻指示器 + 浮层队列**，不占导航位（常态队列很短，页面是过度结构）；
- 人只有一个开工入口：控制台对话（CLI 不再创建任务）。

视觉令牌、组件基元、3D 舞台、对话单输入链路（ADR 0022）全部保留。

## 1. 用户目标（来自产品口径，不是我的推测）

| 来源 | 用户要什么 | 对界面的含义 |
|---|---|---|
| US-001 | 描述目标就建任务 | 入口必须能"直接说"，不能先选表单 |
| US-006 | 高风险操作前得到我的授权 | 授权必须在我看得到的地方出现，且能判断风险 |
| US-007 | 结果要被验收，不能听 Agent 自述 | "完成"必须带验收证据 |
| US-008 | 完成背后要能看到 diff、命令输出、验收结果 | 证据是详情页的**主结构**，不是折叠的附属品 |
| PRD 一句话定位 | 可验收、可恢复、可解释 | 恢复动作和解释（决策理由）必须可点、可读 |

### 2.3 七个结构性问题

| # | 现象 | 代码事实 | 后果 |
|---|---|---|---|
| 1 | 注意力分散在四处，且都不可靠 | app bar 的 `note()` 文案（`AppLayout.tsx:69-91`，`<860px` 被隐藏）、rail 徽标（仅审批）、任务详情内 pending 横幅（`TasksView.tsx:238-259`）、会话内授权卡 | 用户不知道该看哪里；窄屏时主要提示消失 |
| 2 | 澄清请求从"待办"视角完全不可见 | `clarification` 只在线程内以消息卡渲染（`ChatView.tsx:2583-2606`），无全局列表 | 线程停在 `waiting` 时，从任务页/审批页都发现不了 |
| 3 | "live" 徽标名不副实 | SSE 事件只追加进 30 条列表（`store.tsx:138-140`）；`refresh()` 仅在 `onSettled` 和手动点击时执行，事件不触发重取 | 显示"已连接"，但任务/审批列表是打开页面那一刻的快照 |
| 4 | 刷新有隐藏副作用 | `refresh()` 自动选中第一个任务（`store.tsx:106-109`） | 点刷新会把右侧内容换掉，用户正在读的详情被替换 |
| 5 | 任务详情是数据堆叠，不是叙事 | 六段同权重（`TasksView.tsx:283-514`）；RunSpine 是 4 格静态条（`:261-281`），与下方证据无关联；diff 默认折叠在 `<details>`（`:347-365`） | "完成了但我不知道该不该信"——证据要滚过三段才看见 |
| 6 | 对象关系断裂：会话 ↔ 运行不可互达 | 路由只有 `/tasks/:id`；审批卡只链到 task（`ApprovalsView.tsx:57-59`）；详情页不显示"来自哪个会话"（`ChatThread.taskId` 已有数据） | 用户回不到"我当时怎么说的" |
| 7 | 队列不可检索 | `features/tasks`、`features/approvals` 内无任何 `search`/filter（grep 无命中） | 任务一多只能靠眼扫 |

> ADR 0029 落地后，`task ↔ thread` 从 0..1 变为 1..1。问题 2 的修法因此简化成“线程列表打标记 + 置顶”，不需要另建全局澄清列表。

### 2.3.1 渲染校正（P0 实测，2026-11-27）

在 `docs/design/baseline/`（不入库）拓了 6 个目的地 × 3 宽度 × 2 主题 = 36 张基线，并在同一会话里跑了 `tells.js`。修正如下：

| 原判断 | 渲染结果 | 处理 |
|---|---|---|
| 注意力分散在**四处** | 实际是**五处**：漏了 `/agents` 底部那条“2 agents are waiting on you”横幅 | 新增：分散处计数改为五 |
| 澄清在任务/审批页不可见 | 成立；且线程列表**行本身**不标记等待，只有详情头部有一个 `waiting` 胶囊 | 修正：置顶 + 行级标记都要做 |
| “live” 名不副实 | 成立（截图里显示 `Reconnecting`，但数据是打开页面那一刻的快照） | 不变 |
| 任务页六段同权重 | 成立；另外 RunSpine 的四个点**同时出现两个橙色**，无图例，分不出“进行中”与“待你决定” | 新增：脊柱需要图例或直接内联状态文字 |
| 队列不可检索 | 成立 | 不变 |
| — | 新发现：时长格式器在英文界面输出 `6分0秒`；`retry` / `request_human` 这类内部枚举直接外露 | 新增两条文案缺陷 |
| — | 新发现：会话页权限下拉是**原生 select**（`#chat-permission`，142×27，`appearance:auto`），UI-SPEC §5 要求 36px + 自绘箭头 | 新增：控件未落规范 |
| — | 新发现：任务页 diffstat 的文件名与增减条相距 ~700px；校验命令列与状态列间距过大 | 新增：证据要就近，不能横向拆散 |
| — | 反证：`/agents` 的 HUD **反而是全站表达最好的一面**（点 + 文字状态、底部花名册、注意力横幅） | 方向修正：新体系直接沿用这套语言，不另造一套 |

`tells` 的机械结论：会话页 4 张（明/暗 × 桌面/手机）全部命中 `native-control`；设置页桌面命中 `oversized-control`（520×42 的整行按钮，文字 13px，比值 3.22）；其余页面或主题均 `CLEAR`。

## 3. 方向（已定）

ADR 0029 已关闭方向选择，此处只留结论：

| 方向 | 结论 | 理由摘要 |
|---|---|---|
| **注意力优先**（外壳） | **采纳** | 用户打开控制台的动机是"有没有要我决定的"与"跑完了吗"，不是巡页 |
| **Run Cockpit**（运行详情内部结构） | **采纳** | 直接兑现 US-007/008；六段堆叠改成证据脊柱 |
| **会话即控制台** | 否 | 证据与对象关系需要横向对照，纵向时间线做不到 |
| **收件箱做第 5 个导航目的地** | 否 | 又变成必须巡的表面；常态队列很短 |
| **审批也塞进会话列表** | 否 | 列表同时承担导航与排水，批准后在手底下重排 |

### 3.1 设计轮判定（2026-11-27，已渲染）

证据：`docs/design/comps/shots/`（不入库）——A / A-浮层 / B / B-空态 / C，各明暗 × 1440/768/390。

| 候选 | 判定 | 渲染依据 |
|---|---|---|
| **A**：rail + app bar 注意力控件 + 浮层队列 | **KEEP**（附 4 处 REVISE） | 三档宽度与明暗均成立；注意力控件是全屏最强的元素；浮层 440px 能同时放下“精确命令 + 影响面 + 拒绝后果” |
| **B**：无 rail，右侧常驻注意力栏 | **REJECT** | 340px 栏只给到 316px 内宽，`git push origin fix/auth-redirect-loop` 被裁掉——而“精确要执行什么”是决策卡的硬要求；常驻吃掉画布 24%；空态是付费的空白；手机端两栏全隐，注意力彻底消失 |
| **C**：决策卡，一个组件三种容器 | **KEEP** | 360 密集版换行后仍能放下典型命令；720 版把 `unit 6 passed · diffScope inside src/auth` 钉在结论旁，正好兑现 US-008 |
| **D**：导航进 app bar（无 rail） | **KEEP 桌面 / REJECT 手机** | 1440 下省出 56px、页头与正文同列；但 ≤860 时**丢了底部导航**，注意力胶囊还被挤成两行 |
| **E**：桌面页签 + 手机底部条 | **KEEP（选定）** | 合取 D 的桌面优点与 A 的拇指区：≥861 页签，≤860 底部条**带文字标签**（比原图标 rail 只能靠 tooltip 读清楚） |

A 的 4 处 REVISE（下一轮修）：

1. **rail 是否还值得存在。** 2 个目的地 + 设置装在 56px 竖条里，视觉上像“残余侧栏”。需要再做一张「导航进 app bar」的对比稿再定，不默默改。
2. **手机底部条。** `space-between` 把 2 个导航项与设置拉散；应分组，设置恒靠右。
3. **浮层脚注文案。** “Nothing else has been waiting longer than 12 minutes.” 是编出来的句子；改成派生事实（最早等待时长）或删掉。
4. **`Open run` 重复。** 同一屏在运行行和卡片脚各出现一次；收敛到一处。

**自我修正记录：** 这轮 comp 自身踩了 4 个坑——`[hidden]` 被组件 `display` 覆盖、`.convo` 按 `100vh` 算导致 composer 压住内容、卡片横向裁切命令、深色主题参数没传——全部已修并重渲。不计入候选判定，但说明“渲染后才判定”不是形式：这里每一条都是看图才发现的。

**诚实的边界：** 3D 现场只验到“2 busy + 1 online + 1 error”这一种组合；其余 presence 组合未渲染（`UNKNOWN`）。真实队列长度分布仍未知（fixtures 里 51 个任务全是单子任务），它决定浮层会不会该升级成页面。

### 3.2 视觉与交互细节（`emil-design-eng` 复核后）

按该 skill 的清单审了 E 稿，下面每一条都已落地并重渲（明暗 × 1440/768/390）。**P2 实现时必须带着这四条令牌走**，否则会退回原样。

| Before | After | Why |
|---|---|---|
| 注意力胶囊用 `accent` 橙红 | `warning` 琥珀（`warning-soft` 底 + `color-mix` 55% 边） | 系统里 `accent` 已表示“运行中”；两个信号共一色会让“在跑”与“等你”分不开 |
| 卡片标题 `15px` | `14px` | 字号阶梯只有 24/16/14/13/11 五级，15px 是越级值 |
| 元信息 `claude-code · attempt 2` 用 11px + `fg-subtle` | 13px + `fg-muted` | 11px 小字 + 4.60:1 刚好压线；升到 13px 后对比度 6.22:1 |
| 按钮只有 hover，无按下反馈 | `:active { transform: scale(0.97) }` + `transform 160ms var(--ease-out)` | 按下必须有即时回应；这是“界面在听你说话”的唯一证据 |
| `transition: colors`（内置缓动） | `--ease-out: cubic-bezier(.23,1,.32,1)`、`--ease-drawer: cubic-bezier(.32,.72,0,1)` | 内置 ease 太软，撑不起“有意为之”的观感 |
| 浮层/抽屉无入场 | `transform-origin` 贴触发侧 + `translateX(±16px)` + `opacity`，抽屉 260ms / 浮层 240ms，`@starting-style` 入场 | 浮层应从触发它的那一侧长出来；两边对称地“从中心弹”是陌生感 |
| hover 规则无门控 | 触屏下关掉 hover 背景 | 触屏点一下会“粘住”高亮，是假阳性 |
| `height: 100vh` | `100dvh` + 安全区内边距 | 手机地址栏伸缩会切掉底部（任务页底部条会被遮） |
| 无 `prefers-reduced-motion` | 全局降为 1ms 过渡 | 减动效不等于零信息，但位移必须停 |
| 按钮文字可被长按选中 | `-webkit-tap-highlight-color: transparent` + `touch-action: manipulation` | 手机上点按钮会蓝闪 / 长按选中文字 |

两条没做、但要写进实施约束的：

1. **⌘K 打开的会话抽屉不入场动画**——键盘触发每天上百次，加动画只会显得慢。这条与“浮层要有入场”不矛盾：区分的是频次，不是层级。
2. **退出比入场快**（入场 240–260ms，退出 180ms）。comp 里只渲了静态帧，退出时长未验（`UNKNOWN`）。

证据：`docs/design/comps/shots/e-*`、`e-queue-*`、`e-threads-*`（不入库）。

### 3.3 v2 方向：Graphite（已定：Warm Ink 放弃）

用户反馈「composer 那块有割裂感、输入样式不好看」，并要求脱离现有遗产重做。于是做了一版**完全新起的视觉层**（`docs/design/comps/v2.css` / `v2.html`，不入库）。

**主张：chrome 全灰阶；颜色只出现在两处——产品有判决的地方（pass/fail）与「需要你」（琥珀）。** 暖色每次出现都意味着“这件事轮到你了”，这是本方向的 signature move。

**composer 的做法（用户抱怨的那块）：**

| Before | After | Why |
|---|---|---|
| 全宽 1px 分隔线 + 字段自己的边框 | 去掉分隔线，改用滚动区底部 **mask 淡出** | 两层线是“割裂感”的直接来源；内容自己消失在输入区之下，比被一条线切断自然 |
| 输入框 / 控件行 / 提示三块分开 | 一个 `--r-shell` 圆角容器包住 textarea + 工具行 | 三行三块看起来像三件东西；一整块才读作“一个输入面” |
| 字段边框用 `line-control`（灰褐重线） | 默认 `line-strong`，`focus-within` 才转琥珀 | 重线压在输入框上显脏；焦点才该变色 |
| 三种圆角（10/6/999）同屏 | 6 控件 / 12 卡片 / 16 输入壳 | 同一小区域三种圆角是未收口信号 |
| 提示文案 `Enter to send · Shift+Enter…` | `⏎ send` `⇧⏎ newline` 两个 kbd 小键 | 等宽小键比一句话短，且能扫 |
| 发送按钮孤悬在右下 | 按钮在容器内、与工具行同基线；有内容时变实底墨色 | 动作应属于输入面，不是一个漂着的圆 |

**色板（`contrast.py` 实测）**：fg `#E6E8EB`/`#12151A`（15.9 / 17.1），fg-2 `#A8AEB6`/`#545B65`（8.75 / 6.40），fg-3 `#7C848E`/`#636B78`（5.17 / 5.02），signal `#F5A524`/`#8A5A00`（9.59 / 5.53），pass `#3FB950`/`#1A7F37`，fail `#F85149`/`#B3261E`。初版三个 `fg-3` 候选值实测 4.25 / 3.79 / 3.25 全部不过线，已重取。

**代价（没有隐藏）：**
- 放弃 Warm Ink 的“暖纸”气质，换成冷中性石墨；产品的温润感会消失，换来与 diff 红绿不争艳的 chrome。
- 真要做，需要改 `tokens.css` + `UI-SPEC §2` + 全部视觉基线，属于 ADR 级变更（新增 ADR 或修订 0019），不能当样式微调。
- 本轮只验了会话页；运行页、Agent 页、设置页在 v2 下未渲染（`UNKNOWN`）。

**渲染中发现并修掉的三个自身缺陷（都只有看图才发现）：** `.need` 类名撞车把圆点撑成 22×30 的色块；`.mobile-nav { display:none }` 写在了媒体查询之后把自己盖掉；窄屏下 `execute 2/4` 与 `open run` 折行。

### 3.4 v3：把「调度」做进页面结构（已定；v8 用流式实现）

用户提出的判据：这个应用是**调度其他 Agent** 的，对话页的上下文要把这一点表现出来；简洁优雅、不堆砌、要有可交互的暗示。

**作为调度方，这页要回答四件事：**谁在干活 / 为什么是他 / 卡在哪 / 花了多少。对话只是这些的“来由”。

**结构结论：调度板（dispatch board），lane 是签名元素。**

| 决定 | 理由 |
|---|---|
| 每个参与方一条 lane，**包括人** | «等你批准»不是横幅，而是这个运行里的一条泳道；这样“为什么停下来”和“谁在跑”在同一个结构里，不需要两套注意力语义 |
| lane 头只放：谁 · 在做什么 · 步骤/尝试 · 耗时/进度 | 这四项就是调度员的扫描面；其余全部下沉 |
| 人的 lane **展开即决策体**，不另起卡片 | 先做的一版在 lane 下又摆了一张同名卡片，同一件事说两遍；现为 lane 内联命令 + 事实 + 两个动作 |
| 排队与已完成压成一行，不与“在跑”同权重 | 不堆砌：只有“在跑”和“等你”需要体积，其余是记录 |
| 「为什么是他」就在派单句末尾可问 | 选择理由（能力匹配 / 负载 / 历史）是调度的核心可解释性，不该藏在跳转后 |

**明确拒绝的五个方案（都是“看起来很调度”但会变成堆砌）：**

1. **静态 RunSpine**（现状 4 格条）——它能被 lane 完全替代，且不表达并行。
2. **右侧上下文第三栏**——与 lane 重复，又回到三栏。
3. **甘特图 / 时间轴可视化**——它是给复盘看的，不是给“现在要不要批”看的；一眼要的是状态，不是历史。
4. **全量事件/日志流**——那是审计面（运行页）的事，对话页只需结论与干颈。
5. **每个 Agent 一张卡**——并行一多就变成卡片墙；lane 的高度不变，扩展的是行数。

**未验（诚实）：** 窄屏 844px 下“板 + 展开的决策 + composer”装不下，Approve 仍在折叠线下，需滚动。我没有用“隐藏事实”去换它（那等于鼓励盲批），记为待定的人机问题。多 Agent 并行 >4 条时的密度也未验。

> 前一条已在 §3.5.4 被解掉：出问题的原因是过程默认展开，不是空间不够；等待态收起后 390px 一屏放得下。

### 3.5 过程流：时态 · 自决 · 内联审批（v4–v7，已渲染）

用户连续三轮推翻上一版：“卡片堆砌”“思考过程要看得见”“默认折叠与高度限制”。四次修订的判定：

| 稿 | 主张 | 判定 | 依据 |
|---|---|---|---|
| v4 | 调度板 + 三种重量（快答 / 脚注 / 一句提议） | KEEP（结构） | lane 表达并行；避免“每 Agent 一张卡”变成卡片墙 |
| v5 | 过程分三段：context / thinking / actions | **REJECT** | 用户指出是“拍扁的流动”：三段是并排的静态分区，不是时间 |
| v6 | 思考与调用按时间交替，只有要拍板的用卡片 | KEEP | 读起来是“正在发生”，不是事后报告 |
| v7 | 三时态 + 自决 + 等你内联 + 跟随尾巴 | KEEP（本轮结论） | 见 3.5.1–3.5.6 |

**v6 的渲染缺陷（看图才发现）**：`max-height: 332px` 的内层滚动把 `delegate`（派单，调度的核心证据）和最后一条 `Waiting on…▍`（唯一的“它还活着”信号）裁在滚动区外，而画布下面还空着 340px。修正：**取消内层滚动**，只留一个滚动容器并跟随尾巴——“composer 不被顶走”由 flex 保证，不需要额外的高度上限。

**口径说明：** v5–v7 的稿子叠在 §3.3 的 Graphite 层（`v2.css`）上渲染。下面的**结构结论与配色无关**；若 §3.3 未被采纳，“颜色只在判决与‘需要你’处出现”“琥珀不用于到达提示”这两条需换成 Warm Ink 的对应约束（UI-SPEC §2 仍把 accent 同时用于主操作与运行中，这是已知冲突，P2 一并收）。

#### 3.5.1 三时态：判据是“有没有结果”，不是“是什么类型”

| 时态 | 视觉 | 规则 |
|---|---|---|
| 已定稿 | 常规对比；`call` 带 `out`（`2 files` / `6 passed` / `exit 1`） | 有结果就是记录 |
| 正在发生 | 唯一一条没有 `out` 的 `call`（呼吸点 + 计时）；最后一条 `thought` 提一档（`--fg`）+ 行尾光标 | 一条流里最多只有一行没有结果，“现在”因此自动唯一 |
| 尚未发生 | 不渲染 | 不伪造进度、不做 skeleton、不转 spinner |

- `context` 恒为已定稿（11px、`--fg-3`、一行、可省略号）：它是“它凭什么知道”，不是过程。
- 新行到达用**中性**背景淡出 900ms。这里修正了早期草案的“暖色高亮”——该方向里琥珀只表示“轮到你了”，用暖色做到达提示会让两种含义撞车。

#### 3.5.2 自决：是判断，不是第 N 个动作

代码事实：失败升级阶梯在 `runtime/recovery/failure.ts`——无副作用失败先 `same_agent_retry`（<2 次），再 `switch_agent`，再 `replan`，最后 `request_human`，每步写 `DecisionRecord` 带 reason。“它自己换 Agent”是**已有机制**，界面必须能表达。

形状：动作一行（动词 + 对象 + 结果），判断两行（做了什么 + 凭什么）。

```text
decided   switch claude-code → codex, same patch plus a jar-sync test
          Same check failed twice and the file is untouched; codex has write access to src/auth and is idle.   why
```

- 动词 `decided` 比 `call` 的动词亮一档（`--fg-2` 加粗）；理由 12px `--fg-3`。
- `why` 紧跟在理由句尾（不是悬浮按钮），点开即“为什么是他”——调度可解释性的落点（ADR 0029 §2.2）。
- 拒绝：不把自决渲染成“第 N 个 call”，也不为它另起一张卡。

#### 3.5.3 「等你」不是流旁边的卡，是流里那一行自己展开

产品事实：审批会把 Task/Subtask 置为 `waiting_approval`（`runtime/acp-run.ts:607-610`），重试不越过审批与 `manual_required`（`acp-retry.ts:73`）。因此**“在跑”与“等你”不可能同时成立**——早期稿子里“流还在跑、旁边又挂一张审批卡”是假状态。

结论：审批 = 流里的最后一行（`you · allow this command once`），下面是证据与动作（命令 / Why / If allowed / If declined / 两个按钮），左侧一道**中性**细线把这一块连起来，彩色只留在 `you` 与琥珀点上。

- 内容必须是产品真能产生的：今天唯一的 runtime 审批是 `sandbox.relax`（`runtime/approval.ts:32-58`，`riskLevel: medium`，TTL 1h，`decisionMode: once`）。所以示例用“放行一条被沙箱拒绝的验证命令，58 分钟后过期”，**不用** `git push`——PRD 的“外发需审批”是注入场景约束，交付类审批属 P8 之后。
- 一屏一个实心动作：`Allow once`；`Decline` 次级，并写清后果（停在 `waiting_approval`，不前进）。
- 窄屏不删信息：`expires` 与 `Medium risk` 换行显示，不隐藏（风险字段不能为了排版消失）。

#### 3.5.4 折叠：在跑看过程，等你只看决定，跑完只看结果

| 状态 | 默认 | 折叠后摘要 |
|---|---|---|
| running | 展开、跟随尾巴 | `working 3:12 · 4 calls · 2 agents` |
| waiting | **收起** | —（决策体在折叠区外，永不折叠） |
| done | **收起** | `done 2:41 · 8 checks passed · 2 files changed` |

- “跑完”的摘要必须带**结果**而不是状态（上一轮提出、本轮落地）。
- 决策体必须放在 `flow-body` 之外：折叠过程**不能**把“等你”藏起来。
- 这条同时解掉 §3.4 记的窄屏未解问题：844px 装不下是因为过程默认展开；收起后 390px 一屏放得下（`v7-waiting-light-390`），无需隐藏任何事实。

#### 3.5.5 动效（仍然只动三处）

| 时刻 | 做法 | 参数 |
|---|---|---|
| 它在跑 | 呼吸点 | `breathe 1.9s ease-in-out infinite`（opacity .35→1，scale .88→1） |
| 它在想 | 行尾光标 | `caret 1s steps(2)` |
| 新行到达 | 中性背景淡出 | `arrive 900ms var(--ease-out)` |
| 你往回翻过 | `N new steps ↓` 胶囊 | `position: sticky`（**不是** absolute：锚在长元素底部的绝对定位，元素底部出屏时永不出现） |

减动效下：呼吸点/光标/胶囊静止但保留（信息不丢），位移取消。不做：假进度条、spinner、骨架 shimmer、打字机。

#### 3.5.6 本轮渲染暴露的实现缺陷（都只有看图才发现）

| 缺陷 | 后果 | 修法 |
|---|---|---|
| `[hidden]` 被组件 `display` 覆盖 | 该藏的记录行照常显示 | 全局 `[hidden] { display: none !important }` |
| 332px 内层滚动 | 藏掉“现在”，画布却空着 | 取消内层滚动，只留一个容器 + 跟随尾巴 |
| `rAF` 里一次性设 `scrollTop` | 字体未就绪时内容不到上限，`scrollTop` 被夹成 0 | `ResizeObserver` + `fonts.ready` 持续贴底 |
| `jump` 胶囊用 absolute | 元素底部在视口外时胶囊永不出现 | 改 `position: sticky` |
| 胶囊箭头方向 | 指上，但“最新”在下面 | 去掉 rotate |
| 写稿工具把闭合标签插进属性 | 页面渲染出 `="verb">`、`<title>` 变正文 | 渲染用例加“字面量标记”自检（现覆盖全部稿子） |
| `tells` 命中 `left-rule` | 琥珀竖线被读成“引用块/重要性标记” | 竖线改中性，彩色只留 `you` |

`tells` 唯一残留是 `default-focus` 误报：`:focus-visible` 在 `@import` 的 `v2.css` 里，扫描只看页面内样式。

**诚实的边界：** 静态帧验不了“跟随尾巴”的手感、呼吸点节奏、胶囊出现/消失时机；真实任务分布仍未知（fixtures 51 个任务全是单子任务），长流（>200 行）需要窗口化尚未做；胶囊浮在内容上会临时遮住一行（Slack 同款取舍）；等待态“默认收起”需要在真实任务里验证会不会让人找不到过程。

证据：`docs/design/comps/v7.html`、`v7.css`、`shots/v7-*`（不入库）。

### 3.6 终稿 v8：一条对话的完整形态（已渲染，可实施）

**配色口径（回答反复出现的疑问）：Warm Ink 已放弃。** v2 / v6 / v7 / v8 全部画在 Graphite 上——“chrome 全灰阶，颜色只出现在判决（通过/未通过）与「需要你」（琥珀）”。本文档里 §3.3 保留的“待拍板”只指**形式采纳流程**（改 `tokens.css` + UI-SPEC §2 + 视觉基线），不是方向未定；P2 第一件事就是这个。

#### 3.6.1 内容口径：文案全部来自代码，不编

用户要求“不要自己编造，要考虑项目实际返回的内容”。为此逐条对过实现，终稿里每一行都能找到出处：

| 界面上的话 | 真实来源 | 备注 |
|---|---|---|
| `正在分析你的请求…` | `runtime/chat/chat-service.ts:934` | 每回合第一行 |
| 思考段（无前缀散文） | `stage: 'thought'`，内容来自 Pi 的 `thinking_delta`（`brain/pi/session.ts:70-73`），截断 4000 字 | 是编排层思考，不是编码 Agent 的 CoT |
| `计划 3 个步骤：定位原因 / 修复并补测试 / 验收` | `runtime/brain-run.ts:252-258`，`titles.join(' / ')` | 连接符就是 ` / ` |
| `读取 src/auth/session.ts` | `toolLabel()`：`读取 {path}` / `执行 {cmd}` / `编辑 {path}` / `搜索` / `抓取`（`chat-service.ts:137-165`） | 产品**不存**原始工具名，本来就只给效果 |
| `执行 pnpm vitest run auth` · `6 项通过` | 同上 + `event.status`；验收结果来自 `verdict` | 见下表的那条待修 |
| `派给 Claude Code：修复 cookie 写入顺序` | `brain-run.ts:520-524`，`派给 ${chosen.name}：${subtask.title}` | 步骤同时带 `agent: chosen.name` |
| `Claude Code 执行完成（验收通过）` | `brain-run.ts:596-600` | 原样是 `（验收 ${verdict}）`，见下 |
| `等待你批准后继续` / `需要你确认：…` | `brain-run.ts:632` / `:210` | 审批与澄清分开 |
| 每 Agent 一段产出（段标题 = 子任务标题） | `chat-service.ts:1027-1036`：每个子任务单独成段，带 `agentName` | 注释写明“一次对话可能派给多个 Agent” |
| `58 分钟后过期 · 中等风险` | `runtime/approval.ts:32-58`：`riskLevel: 'medium'`、TTL 1h、`decisionMode: 'once'` | 时长是真数据，不是文案 |
| `拒绝后：任务停在「待你审批」` | `acp-run.ts:607-610` 置 `waiting_approval`；`acp-retry.ts:73` 不越过审批 | 所以状态文案可断言 |

**代码里有一处会漏枚举，需随实现修：** `执行完成（验收 ${result.verdict}）` 直接拼 `pass` / `fail` / `manual_required`，界面会显示`（验收 pass）`。终稿显示为`（验收通过）`，意味着要把 `verdict` 映射成 通过 / 未通过 / 需人工（i18n 里已有 `statusPass: '已通过'` 可复用）。

#### 3.6.2 结构：线条是过程，唯一的容器是「轮到你」

```
你的问题（右侧气泡）
└ 执行过程  ── 12 步 · 用时 3:12                 ← 一行可折叠；在跑时展开
   ├ [图标] 正在分析你的请求…
   ├ [图标] 思考一段（散文）
   ├ [图标] 计划 3 个步骤：…
   ├ [图标] 读取 src/auth/session.ts        完成
   ├ [图标] 执行 pnpm vitest run auth       6 项通过
   ├ [CC]   派给 Claude Code：修复 cookie 写入顺序
   ├ [DSH]  派给 DSH：补 Safari 回归用例
   ├ [DSH]  DSH 执行完成（验收通过）         1 个文件
   └ [CC]   Claude Code 执行中              ● 0:48   ← 反色徽标 + 脉冲环
└ ⎡ 你 · 允许执行一次           58 分钟后过期 · 中等风险 ⎤  ← 唯一的框
  ⎢ pnpm test:e2e -- auth                                  ⎥
  ⎢ 为什么 / 允许后 / 拒绝后                                  ⎥
  ⎣ [允许一次] [拒绝]                                        ⎦
└ [CC]  修复 cookie 写入顺序   （产出段，带 +18 −6）
└ [DSH] 补 Safari 回归用例     （产出段，带 +34）
└ 验收 8 项通过 · 用时 3:12 · 打开任务
```

- **一条过程 = 一行**：`18px 身份位 + 说明`，结果紧跟在说明后面（`读取 src/auth/session.ts · 完成`）。
- **不画横线**（用户反馈“每行都用线分隔不美观”）：节奏靠留白、身份位的垂直对齐，以及分段处的 12px 空隙（派单前、验收前）；状态用 `·` 连接而不是另起一列，避免变成“缺格的表格”。
- **五个图标就够了**：activity / message / tasks / tool / agent 徽标（用现成图标集 `Icon.tsx` 的语义，不新造图形语言）。
- **调度不靠一张图**：每条派单一行，并行就是相邻两行；同一 Agent 的产出另起一段。这比 §3.4 的“板”更轻，代价是同一 Agent 多次派单会分散在多行（板能聚成一条 lane）。
- **产出一律带归属**：段头是 Agent 徽标 + 子任务标题，避免“不知道是谁说的”。

#### 3.6.2b 折叠与展开：箭头在左，图标就地换

| 项 | 做法 |
|---|---|
| 折叠箭头 | 在行的**最左侧**（对齐 18px 身份位），右向箭头 → 展开后转 90°；状态不再另放一颗点，直接用颜色：`执行中` 中性 / `等待你处理` 琥珀 / `已完成` 绿 |
| 可展开的行 | 悬停时，**原来那个图标就地变成展开箭头**（同一个 18px 槽，交叉淡入 120ms）——不是并排两个图标，18px 里并排必挤 |
| 展开后的证据 | 用一块 `--raised` 背景（圆角 8）装命令与输出，不再用横线分区 |
| 不可展开的行 | 思考/计划这类纯叙述行不加箭头，避免满屏都是可点的暗示 |

#### 3.6.3 Agent 的身份位：为什么是首字母徽标

用户提“带点各 Agent 的 logo 提升美感、简化提示文字”。仓库与目录（`catalog/builtin.json`：DSH / Hermes / WorkBuddy / Qwen Code / Claude Code / Codex）都**没有官方图形素材**，凭空画别家的标是不该做的事。因此：

| 项 | 做法 | 理由 |
|---|---|---|
| 身份位 | 18px 圆角方牌，首字母（`CC` / `DSH` / `QC` / `HB`），单色 | 与 chrome 同一套语言；不抢琥珀与红绿 |
| 运行中 | **反色**（深底浅字）+ 常驻淡环 + 1.8s 脉冲环 | 静态帧也能看出“是它在跑”；不靠转圈 spinner（§3.2 禁） |
| 你的身份位 | 琥珀描边 + `你` | 人也是一条 lane（§3.4 结论） |
| 以后换 logo | 槽位尺寸、圆角、对齐不变，直接替换内容 | 不需要重排版 |

#### 3.6.4 三态默认（与 §3.5.4 一致，实测确认）

| 状态 | 过程块 | 为什么 |
|---|---|---|
| 在跑 | **展开**，尾巴跟随 | 此刻唯一要看的确实是过程 |
| 等你 | **收起** | 实测：展开 11 行会把批准按钮顶到折叠线下（1440×1000 也会）；收起后 390 一屏放得下 |
| 跑完 | **收起** | 摘要带结果：`已完成 · 12 步 · 用时 3:12`，下面直接是两段产出与验收结论 |

#### 3.6.7 边界

- 只验了 1440×1000 / 1440×1560 / 390×844 三档与明暗；**没有**在真实 daemon + 真实 Agent 上跑过（数据是照着事件字段构造的，虽然逐条对过代码）。
- 并行 >2 个 Agent 时的行密度未验（现在是 2）；同一 Agent 多次派单在流里会分散。
- 徽标是替代品；换成官方 logo 需先确认素材与*授权*（ADR 级的小决定）。
- `verdict` 未映射前，真实界面会出现 `（验收 pass）`——实施顺序上这条要在 P6 之前修。
- 悬停换图标只对“有指针”的设备成立；触屏要另给持久入口（长按或右侧常驻箭头），本轮未验。

证据：`docs/design/comps/v8.html`、`v8.css`、`shots/v8-{waiting,done,done-open,full,motion,hover,detail}-*`（不入库）。仍在 `snowe-ui-skill`（证据优先、`tells` 无命中）与 `emilkowalski/skills`（动效只动三处、减动效退化）的框架内。

### 3.7 终稿 v9：把「谁在跑」收敛到输入框上方

用户三点反馈：① v8 的授权卡片不如 v7 简洁；② v4 那个“统一入口看到运行中 Agent 状况”的做法好；③ 能不能收敛、固定在输入框上面、可折叠展开（类似 Codex 分批执行）。

#### 3.7.1 角色分工：记录 vs 现在

这是本版唯一的结构原则，也是去重的手段：

| 区域 | 回答的问题 | 内容 |
|---|---|---|
| 对话（transcript） | **发生过什么** | 提问、推理与工具步骤、审批记录、每个 Agent 的产出、验收结论 |
| dock（输入框上方） | **现在怎么了** | 状态（执行中 / 等待你处理 / 已完成）、参与的 Agent 与它们的当前状态、待你仲裁的事 |

因此两处**不再重复同一句话**：过程头改成`执行过程 · N 步 · 用时`（只说这一段是什么），状态字样只出现在 dock 头。

#### 3.7.2 三件具体改动

| 项 | v8 | v9 |
|---|---|---|
| 授权内容 | 带琥珀描边的独立容器 + 「你」徽标 | **不再套内框**：标题 / 命令 / 三问 / 两个按钮直接排，去掉「你」徽标与竖线；“轮到你”由 dock 头的琥珀色与实心按钮表达 |
| 运行中的 Agent | 散在过程流里的“派给/执行中/完成”逐行 | **收进 dock**：一行一个 Agent（`[CC] Claude Code · 修复 cookie 写入顺序 · 0:48`），可折叠 |
| 过程流 | 12 步（含 5 条 Agent 记录） | **7 步**：只剩推理与工具。派单/完成不再占流的位置 |

#### 3.7.3 dock 的形态

- **它本身是一张卡片**（surface 底 + 1px 边 + 12 圆角，无阴影），与输入框之间留 8px。理由：不加容器时，状态条会和上方对话内容、下方输入框糊成一片，分不出"现在"到哪儿结束（用户实测反馈）。卡片只有一层：**内部不再套框、不画竖线**。
- **位置**：输入框正上方、同宽（720），随对话区伸缩；它不遮内容，也不浮动在内容上。
- **折叠头**：左侧箭头（与过程头同一个位置和交互）+ 状态 + 右侧元信息。**右侧这个位置按状态给不同内容**，不能由子组件各自去写：
  - 执行中 → `2 个 Agent · 1:12`
  - 等待你处理 → `3 个待审批`（条数就是要判断的信息，不是“第几条”）
  - 已完成 → `2 个 Agent`（验收结论留在对话的收尾行，不在这里重复）
- **展开体**（与过程行同一套：18px 身份位 + 说明 + 行内状态）：
  - 在跑 / 跑完：Agent 行；在跑的那个徽标反色 + 脉冲环
  - 等你：直接是决策体（标题 / 命令 / 为什么·允许后·拒绝后 / 两个按钮）
- **多条待审批：一次只放一条（v9 二次修正）**。三条同时摊开会把决策体顶出屏幕，所以：
  - 只渲染当前一条；决定后旧卡左滑出（160ms）、下一条右滑入（160ms），高度随内容变；`prefers-reduced-motion` 下直接切换，不做位移；
  - 全部批完 → dock 头回到 `执行中`，末行给一句 `审批已通过：续跑同一 execution 的验收（不重跑 Agent）。`（这是真实文案）；
  - 顶栏的全局指示器与 dock 报**同一个数**；没有待批的事时指示器整块隐藏——同屏两处对不上，比少一个入口更伤人。
- **默认展开**：在跑展开（你在看）、等你展开（要你拍板）、跑完收起（它是记录）。`?dock=0/1` 可强制。
- **窄屏**：390 下“dock 展开 + 决策体 + 输入框”一屏放得下（已验）；过程流收起，不抢空间。

#### 3.7.4 取舍与边界

- **代价：同一段运行被两个区域描述**。靠“记录 vs 现在”分工，但仍可能出现同屏两处提到同一件事；本版已把“验收 8 项通过”从 dock 里拿掉。再加东西前先问：这是“发生过的”还是“现在的”。
- 过程流不再展示“派给谁”这一步——它在 dock 里，且是持续可见的（比滚动到底才能看到更可靠）。若将来需要审计级的完整时间线，那是任务页（P5）的事。
- 授权放在输入框上方，等于“你下一次输入前的上下文”。**多条并发审批已改为队列**（§3.7.3），但 >3 条时的节奏与高度变化未验；若长到 8 条以上，按 ADR 0029 的复审触发条件考虑升级成页面。
- 实现期坑（本轮实际踩到）：轮播脚本曾无条件改写 dock 头的元信息，把「执行中 / 已完成」也写成「3 个待审批」。**同一个文本位只能有一个写者，且必须按状态分支**——这与 `.run` / `.need` 撞名、`[hidden]` 被组件 `display` 覆盖是同一类错误：共享槽位谁都能写，就会写错。
- 未在真实 daemon 上跑过；`verdict` 映射、触屏无 hover 这两条旧帐仍在。

证据：`docs/design/comps/v9.html`、`v9.css`、`shots/v9-{waiting,waiting-2,waiting-3,approved,done,done-open,full}-*`（不入库）。全量渲染 155 例通过，`tells` 只剩已知的 `default-focus` 误报（`:focus-visible` 在 import 的 `v2.css` 里，扫描只读页面内样式）。

**本版取代 §3.6 的两处：**（a）审批不再是“唯一的框”，改为无框竖线；（b）派单/完成行移出过程流，进 dock。其余（文案出处、三态默认、动效三处、徽标）继续适用。

### 3.8 UI 规范（可实施口径，代码即事实）

> **用途：** 以后任何人（或 agent）改控制台，以本节的数值实现，不再翻设计稿。
> **2026-11-28 变更（ADR 0033）：** 表面语言已改为「零线条 + 色阶分区 + 三栏就地折叠」，口径见 `docs/UI-SPEC.md` §12。**本节仍是当前代码的实况**；§12 落地时随代码一起改写本节，不要只改一处。
> **来源：** `docs/design/comps/v2.css`（Graphite 令牌 + 会话骨架）、`v9.css`（过程流/dock）、`e.html`（壳层与抽屉）。
> **代码位置：** `packages/web/src/styles/tokens.css`（唯一色源）、`app/AppLayout.tsx`（壳）、`features/chat/*`（对话页）、`features/inbox/*`（决策）。

#### 3.8.1 色彩层次（最容易做错的一条）

四个面必须**是四个不同的值**，否则卡片会糊在背景里（本轮真实踩到：对话区误用 `surface`，导致 dock 与输入框全部隐形）：

| 层 | token | Light | Dark | 用在哪 |
|---|---|---|---|---|
| 画布 | `--hx-bg-canvas` | `#F6F7F9` | `#0B0C0E` | 页面底、**对话区背景**、命令块底 |
| 卡片 | `--hx-bg-surface` | `#FFFFFF` | `#111316` | dock 卡片、弹层、面板 |
| 抬升面 | `--hx-bg-raised` | `#FFFFFF` | `#171A1E` | **输入壳**、用户气泡、激活页签、icon-btn hover |
| 次级块 | `--hx-bg-subtle` | `#F1F3F6` | `#171A1E` | 证据块、代码块、（暗色下与 raised 同值） |

文字三档：`fg-default` / `fg-muted` / `fg-subtle`；边框三档：`line-subtle` / `line-default` / `line-control`（控件）。完整值与对比度见 `docs/UI-SPEC.md` §2 与 ADR 0030。

**颜色语义：** 彩色只有三处——`success`（判决通过）、`danger`（判决未通过）、`accent`=signal（**只表示「需要你」**）。主按钮用 `fg-default` 实底，不用 accent。

#### 3.8.2 排版与量度

| 项 | 值 |
|---|---|
| 正文 | 14px / 行高 1.55 / `-0.006em` |
| 会话标题 | 17px / 600 / 1.35（`.switch`） |
| 段落标题（决策卡） | 14px / 600 |
| 元信息 | 11px / `fg-subtle`；状态词用 `fg-muted` |
| 等宽 | JetBrains Mono 12px（命令、路径、id） |
| 内容量度 | **720px 居中**（头部 / 正文 / dock / 输入框四者共用） |
| 圆角 | 控件 6 / 卡片 12 / 输入壳 16（三档，不许出现第四种） |
| 行内分隔 | 用 `·` + 间距，**不用竖线、不用分割线** |

#### 3.8.3 顶栏（`AppLayout`）

| 元素 | 规格 |
|---|---|
| 高度 | 50px（≤860px 为 48px），下边线 `line-subtle`，底色 canvas |
| 品牌 | 18–20px 字形，色 accent，只做链接，不做按钮 |
| 页签 | **纯文字**（无图标）：30px 高、`px-2.5`、13px/500、idle `fg-3`；激活 = 600 + `bg-raised` |
| 注意力 | 30px 方块（**不是胶囊**）：`bg-accent-soft` + `1px color-mix(accent 38%)` + accent 文字 13px/600；内含 7px 圆点、`N 项等你处理`、11px/400 `N 项待审批`（≤860px 隐藏最后一段）；`:active { scale(.97) }`；**计数为 0 时不渲染** |
| 连接 | 点 + 文字（11px `fg-3`），**不做胶囊、不加边框**；`title` 里带“最后更新” |
| 右侧控件 | 只有设置（30×30）。**不放刷新**（刷新在 ⌘K） |
| 移动端 | ≤860px 隐藏页签/连接/设置，改底部条（48px + 安全区，图标 + 文字） |
| 深链页 | 任务/审批/设置 在顶栏显示页面名；**Agent 页不显示**（目的地页签已写着 Agent，再排一个同名页名会被读成两个页签；现场/接入 由页面内的分段控件表达）；对话页由线程标题表达 |

#### 3.8.4 会话抽屉（E 稿）

遮罩 `rgb(0 0 0 / 20%)`；面板宽 280（`max 88vw`）、`bg-canvas`、右边线 `line-subtle`；入场从 `translateX(-16px)` 240ms `ease-drawer`，减动效直接出现。

结构：`会话` 标题（13px/600）+ 关闭 → **`+`（32px 图标按钮）+ 搜索框（32px，`line-subtle` 边，`bg-surface`）同一行** → 按工作区分组的列表（`gap 2px`）。

**历史只算「有内容」的会话：** `messageCount = 0` 的线程不进列表（迁移前点「新会话」留下的空线程会被自然过滤）。新建用头部搜索框左边的 `+`：先选目录，**不写库**，回到空对话页；真正建线程发生在第一条消息发送时，标题也从那句话里取（`send`）。所以列表里不会出现 “New thread”。

分组：同一 `worktree` 的会话归为一组，组头是短路径（`~/adstudio`；无工作区显示「未指定工作区」）；组的顺序就是组内最新会话的顺序。
行 = 标题（13px，激活 600 / 其余 500）+ 次行（11px `fg-3`：`状态点 · 状态 · N 项等你处理 · 相对时间`）。状态点：在跑中性、完成 success、失败 danger、等待 warning。
行被动：悬停/聚焦显示 `⋯`。操作菜单（重命名 / 归档 / 删除）是 `fixed` 浮层，**`z` 必须高于抽屉本体**（抽屉 `z-50` → 菜单 `z-[70]`、透明遮罩 `z-[60]`），否则菜单会被抽屉盖住到看不见。
打开时聚焦搜索框；Esc / 点遮罩关闭；点条目先关抽屉再跳转。

#### 3.8.5 对话页骨架

| 区域 | 规格 |
|---|---|
| 头部 | `padding 18/20/14`、**无下边线**；标题按钮（17px/600 + 11–14px chevron）+ 副行（11px：`~/dev/... · 权限档`）；右上只有一个 `⋯` **文本**菜单（无图标） |
| 正文 | `padding 4/20/28`，`gap 22px`，720px 居中；**滚动区底部 40px 用 `mask-image` 淡出**，不用横线切断 |
| 用户气泡 | 右对齐，`max-width min(70%,60ch)`，`bg-raised` + `1px line-subtle` + 12px 圆角 + `padding 9/12`；**无时间戳、无小尾巴** |
| 助手侧 | **无头像、无「HubAgent · 时间」**；只有过程折叠行与产出 |
| agent 产出 | 18px 首字母徽标（`bg-ink`/`text-canvas`，9px）+ 14px/600 标题 + 正文（后端格式 `**标题**\n\n正文`） |
| 过程流 | 一行：18px chevron 槽 + `执行过程` + 右侧 `N 步 · 用时 X`；**无框无底色**；展开后步骤左对齐同一 18px 槽，行距 6px；步骤状态用图标颜色表达，不额外加字 |
| 工具行 | 悬停时 18px 槽内图标交叉淡入为箭头，展开转 90°；证据块 `bg-subtle` + 12px 圆角（不再套边框） |
| 任务/文件 chip | 只在**完成 / 失败**时出现在收尾处（对应 v9 的「验收 N 项通过 · 用时 · 打开任务」） |

#### 3.8.6 dock（输入框上方）

外框：`padding 12/20/8`（与正文 12px、与输入框 8px）；卡片 = `bg-surface` + `1px line-subtle` + **12px 圆角**、`padding 8/12/10`、**无阴影**。
头行：18px chevron 槽 + 状态词（13px/500，在跑 `fg-2`、等你 warning、完成 success、失败 danger）+ 右侧元信息（11px `tabular-nums`）。
元信息**按状态给不同内容，且只由 dock 写**：在跑 → `N 个 Agent · m:ss`；等你 → `N 个待审批`；完成 → `N 个 Agent`。
体：等你 → 决策体；在跑/完成 → Agent 行（徽标 + 名称 + `· 子任务` + 行内状态，`padding 3px 0`、12.5px）。
默认展开：在跑 / 等你；完成收起。用户手动改过后按 thread 记住。

#### 3.8.7 决策体（dock 与浮层共用 `DecisionBody`）

无内框、无竖线、无「你」徽标。结构：
1. 标题 = 动作（`sandbox.relax` → **允许执行一次**；未知动作回退为 reason），右侧元信息 = `N 分钟后过期 · 中等风险`（`expiresAt` 缺失时只显示风险；已过期显示`已过期`）。
2. 命令块：`bg-canvas` + `1px line-subtle` + 8px 圆角 + `padding 7/11`、等宽 12px。
3. facts 三行：`为什么`（reason）/ `允许后` / `拒绝后`；标签列 `5.5rem` 固定宽（避免 `If approved` 折行）。
4. 动作：`允许一次`（primary 实底）+ `拒绝`（ghost）；有队列时右下角 `还剩 N 条`。

> 「所在任务」不进决策体（v9 删掉了）：dock 本身就在该线程里，任务入口在收尾行。

#### 3.8.8 输入框（一整块）

`padding 0/20/18`，**无上边框、与页面同底色**（底部不分割）。壳 = `bg-raised` + `1px line-strong` + **16px 圆角** + `padding 12/12/9` + 双层软阴影；`focus-within` 时边框转 `color-mix(accent 45%)`。
textarea 无边框、`min-height 48`、`padding 2/4`、行高 1.5。
控件行 `pt-2 gap-1.5`：**没有工作区 chip**（工作区只在建会话时由抽屉的 `+` 选一次）→ 权限下拉（无边框、`fg-3`，盾图标 12px + 原生 select + 11px chevron）→ 运行设置（**只有图标** 13px，非默认时右上一个小圆点）→ 弹性空白 → `⏎ 发送` `⇧⏎ 换行`（11px `fg-3`，kbd 10px 带边框，≤560px 隐藏）→ 发送按钮 30px 圆形、`bg-ink`、`text-canvas`；`:active scale(.94)`；disabled 用 `line-strong` 底 + `fg-3` 字。
控件行**不再用带边框的按钮样式**：这三件是“附着在输入壳里的设置”，再套三层边框会把注意力从输入本身抢走。

#### 3.8.9 浮层队列（`InboxPanel`）

原生 `<dialog>`（焦点陷阱 / Esc / 顶层堆叠由平台给）。一次一条 + 右下角剩余数；决定后旧卡左滑出 160ms、下一条右滑入 160ms；`prefers-reduced-motion` 直接切换。每次打开重置已处理集合。

#### 3.8.10 动效与降级

只动三处：加载点、流式游标、队列换条；抽屉入场 240ms / 退出 180ms；按钮按下 `scale(.97/.94)`；`hover` 规则只在 `(hover: hover) and (pointer: fine)` 下生效；`prefers-reduced-motion` 下位移归零、只保留透明度。缓动取 `--hx-ease-out` / `--hx-ease-drawer`，不用内置 ease。

#### 3.8.11 主题

只用 `light-dark()`，由 `<meta name="color-scheme">` 切换（`shared/theme.ts`），不写两套类名。**每个包含背景色的组件都要在两种主题下过一遍**：检查项＝画布/卡片/抬升面是否仍可区分、边框是否可见、accent 文字是否够对比。

#### 3.8.12 任务页（`/tasks`、`/tasks/:id`）

一句判决 + 一条竖向证据脊柱，**不再是六段同权重**。量度与对话页同一条 720px。

| 项 | 规格 |
|---|---|
| 头部 | `18/20/14`；来源对话（11px 链接，取不到就不显示——不编标题）→ 标题 17px/600 → 副行 11px：`N 次执行 · N 个子任务 · N 项检查 · <sha8>` |
| 判决条 | 无框，一行：状态词 14px/600（通过 `success` / 未通过 `danger` / 等你 `accent` / 取消 `fg`）+ **紧挨着的 diffstat** + 右侧 11px 元信息 |
| diffstat | `+n −n` **只从 `git diff --stat` 的 summary 行取**；文件行里的 `++++---` 是按比例画的条，数它等于把图形当数据 |
| 未通过 | 判决下面直接给「最近一条」失败检查：命令 + 退出码 + `outputRef`；不展开、不点击就能看见 |
| 脊柱 | `<ol>`；节点 = 18px 标记槽 + 内容（左缩进 28px）；连接线 1px `line-strong`，画到下一个节点里，最后一个不画；标记 9px + `ring-4 ring-canvas` 在线「上打孔」 |
| 节点态 | 灰=已发生 / 深=在跑 / 红=失败 / 琥珀=等你 / 空心=未到；**不加动效**（动效只有加载点、流式游标、队列换条三处） |
| 阶段顺序 | 计划（默认收起）→ 需要你（有则常驻展开，不设箭头）→ 执行 → 验收 → 记录（默认收起、标题退到 `fg-2`） |
| 执行 | 一次尝试一行头：`第 N 次 · Agent · 结果 · 分支 · sha · 用时`；文件清单一级可见（只给路径）；补丁进 `<details>`；失败那一次用**归因词**（协议/Agent/资源/验收/预算）说明为什么 |
| 验收 | 检查表：图标 + kind + 命令 + 退出码（失败行 `danger`）；元信息只说「由 Runtime 执行」，不重复条数 |
| 失败动作 | 就地两个：`回到对话继续修`（实底）+ `复制失败详情`（虚线按钮）。**没有重试/取消**——端点不存在，不放假按钮 |
| 记录 | 决策（类型 + 相对时间 + 理由）+ 最近事件（按时间**正序**，虚线引导）；事件条数 0 时不显示这一段 |
| 画布上的块 | 命令块与补丁块用 `subtle`（不是 `canvas`）：亮色下稍深、暗色下稍亮，两种主题都读得出来。**块在卡片里用 `canvas`，块在画布上用 `subtle`** |
| 列表行 | 7px 状态点 + 标题 13px/500 + 次行 11px（状态 · `N 项待处理`）+ 右侧相对时间；行内 `px-2`、hover `raised`、行间不加分隔线；筛选条与行同缩进 |

**已知缺口（写下来，不靠记忆）：**

- 失败节点只有两个动作：重试/取消运行需要后端端点，今天没有。
- 事件是 SSE 的最近 30 条（按 `goalId` 过滤，也就是本任务）。审计级完整时间线需要 `GET /api/v1/tasks/:id/events`，未做。
- 列表行只写 `status`、`createdAt`、待审批数——列表接口没有 Agent 数与 diffstat，所以行里不写这些。

#### 3.8.13 Agent 页（`/agents` 现场、`/registry` 接入）

一个目的地、两个分段，**分段控件在页面里**（不在顶栏）：顶栏 ≤560px 会把分段藏掉，那时手机上就无法切换。

| 项 | 规格 |
|---|---|
| 页面骨架 | 分段行（`px-5 pt-3`，≤860 `px-4 pt-2`）+ 内容区 `flex-1 min-h-0`；整页不滚动，由各分段自己滚 |
| 分段控件 | 30px、`px-2.5`、13px/500，激活 = 600 + `bg-raised`（与顶栏页签同一套）；**不做胶囊、不做底色槽**；`aria-current="page"`；`/registry` 路径保留，书签不失效 |
| 现场 | 3D 面板在 `p-4`（≤860 `p-3`）里铺满，`rounded-panel + 1px line`；**HUD 按 861px 分档**：镜头预设与地板标签只在 ≥861 显示（窄屏会与派发卡叠在一起），派发卡 `max-w-[calc(100%-2rem)]` |
| 接入 | 720px 居中列；工具栏与行同缩进（`px-2`）；行 = 7px 状态点 + 名称 13px/500 + 次行 11px（状态 · 不可接入）+ 路径 mono 11px；无分隔线、hover `raised` |

| 零 Agent | 两处空态都给可执行的那一步：现场空态 → 「去接入一个」+ CLI 注册命令；接入空态 → 扫描 + CLI 注册命令（`hubagent agent add --name … --cmd …`） |

#### 3.8.14 运行设置与交付（P8）

两个「只有 CLI 才能设」的旋钮进会话（`chat_threads.run_settings`），交付是任务页的一次显式动作。
**没有预算面板**：成本/用量在运行时没有计量源，旋钮只能是摆设（ADR 0031）。

| 项 | 规格 |
|---|---|
| 入口 | 输入框控件行的一个 chip（`settings` 图标 + 「运行设置」），≤560px 只留图标 + `aria-label`；非默认时带一个 6px **中性** 圆点（不是 accent——它不表示「需要你」） |
| 只影响之后的回合 | 面板首行直说；正在跑的回合不被改写（事后改验收命令等于事后改判） |
| 可用 Agent | 复选 chips；**一个都不勾 = 全部**。它只是「Brain 能在谁里派单」的范围，不是手动拆派 |
| 验收命令 | 多行输入 + 添加/移除；退出码 0 为通过（超时 10 分钟，与 CLI 一致）。**不填时只剩 diffScope**，面板里直说「那证明不了任务做成了」 |
| 后台执行 | 不给开关：控制台本来就在 daemon 侧跑（`void this.run`），面板里说明“关掉页面不会中断” |
| 交付 | 验收通过 + 有补丁时，判决条下方给「导出补丁」（`patch-export`），结果路径**留在页面上**而不是一闪而过的 toast；`branch-only` 是默认结果，不需要动作 |

**不做（ADR 0031，已从口径里删掉，不是欠账）：**

- **预算**：会话级预算旋钮已移除。运行时保留不可配置的护栏（回合动作数 16、token 估算上限、回合 90s；委派墙钟），但它们服务于“不让进程挂死”，不是费用控制。
- **`auto-merge`**：从交付模式与类型里删除；依赖未落地的 `targetRef` / `autoMerge`，且把“是否进主干”从人手里拿走。
- **交付记录表**：不建。结果随响应返回，补丁路径由 `taskId` 确定性推回；任务是否完成由 `completeTaskAfterDelivery` 表达。
- **门禁状态**：ADR 0029 §2.4 收窄为四项且均已可用；`ha run` 本体的关闭是另一轮工作（ADR 0031 §5）。

## 4. 目标 IA（ADR 0029 §2.2）

### 4.1 导航（2 个目的地 + 设置）

**形态（P1 判定 E）：** ≥861px 用 app bar 文本页签；≤860px 用底部条（带文字标签）。**原 56px 图标 rail 取消**——只装 2 个目的地时它像一条残余侧栏。

**会话历史（评审补）：** 入口是**当前对话标题本身**——标题右侧的 chevron 表明它可以切换，点开左侧抽屉：搜索框 + 历史列表 + 「New conversation」。⌘K 直达同一列表。

抽屉每一行带状态与「2 need you」，所以它同时回答两件事：「我有哪些对话」与「哪个在等我」。这也是取消常驻列表后不能靠快捷键当唯一入口的原因——历史必须可见可点。

| 目的地 | 路径 | 内容 | 徽标语义 |
|---|---|---|---|
| 对话 | `/`、`/chat`、`/chat/:id` | 线程抽屉 + 单栏会话 + 条件性上下文；**唯一开工入口** | 等你回答的线程数 |
| Agent | `/agents`（现场 / 接入 分段，分段控件在页面内） | 3D 工位 + 接入配置合并为一个目的地 | 故障 / 待认证 |
| 设置 | `/settings` | 主题 / 语言 / 模型 | — |

**运行**：`/tasks`、`/tasks/:id` 保留（可深链、可书签、可筛选），不占导航位——它是对象，不是地点。
**兼容**：`/approvals` 保留为深链（等价于收件箱的审批筛选）；路径不改名，只改分组。

### 4.2 注意力：常驻指示器 + 浮层队列

- 位置：app bar，`轮到你 N`；**`<860px` 不隐藏**（现状是隐藏的，属于缺陷）。
- 判据：**系统已停下等人做决定，而人还没做**。运行中的工作、通知历史、无决定的完成项都不进。
- 内容与归属：

| 类别 | 归谁 | 处理位置 |
|---|---|---|
| 待审批 | 运行 | 浮层内就地批准/拒绝；完整证据跳运行页 |
| 待澄清 | 会话 | 线程标记 + 置顶；线程内就地作答 |
| 失败待决策 | 运行 | 浮层给三选一；证据在运行页 |
| 完成待复核 | 运行 | 默认折叠成一行计数，不逐条催 |

- 每条必须回答：谁在等 / 精确要执行什么 / 为什么有风险 / 影响范围 / 不做会怎样。一屏一个实心动作。
- 数据可行性：审批、失败今天可派生；逐条澄清走 `GET /api/v1/clarifications/:id`；**按"等最久"排序今天算不出来**（`ApprovalRow` 无时间字段），需先按 风险 → 类型 → 任务创建时间 排。

### 4.3 对象关系（补齐断链）

```text
Goal ── 1:1 ── Thread（对话）── 1:1 ── Task（运行，ADR 0029 后必有会话）
                                        ├── Subtask
                                        ├── Execution（attempt / 工作区 / diff / commit）
                                        ├── Verification（checks + 证据）
                                        ├── Decision（Brain 理由）
                                        └── Approval（人等在这里）
```

界面上必须双向可达：运行详情显示"来自对话《标题》"，对话回合可回到运行，审批卡同时给出两者入口。

## 5. 交互原则（可验收，落到评审清单）

1. **一屏一个主操作。** 浮层里每个决策对象只有一个实心按钮（批准），其余次级或文本。
2. **注意力只在一个地方计数，且窄屏不消失。**
3. **"能看见状态"不等于"能判断"。** 决策对象必须给全五个问题（§4.2）。
4. **证据在结论旁边。** 运行的"通过/失败"旁边就是 diffstat 与最近一条失败 check。
5. **连接状态必须诚实。** `live / connecting / offline` 附"最后更新"；离线时禁止暗示数据是新的。
6. **不隐藏后果。** 破坏性动作（拒绝审批、取消运行）走确认，说明会发生什么。
7. **对象不丢。** 深链刷新后仍落到同一对象；每个空态都有下一步。
8. **一次只动一处。** 状态变化才动，`prefers-reduced-motion` 下退化为静态。

### 6.2 视觉稿的优先级（哪块以哪份稿为准）

用户 2026-11-27 确认的口径，实现按此对齐：

| 区域 | 以哪份稿为准 | 落在哪里 |
|---|---|---|
| 壳层：app bar 两个页签、注意力指示器、移动端底部条 | **E 稿**（`docs/design/comps/e.html`） | `app/AppLayout.tsx` |
| 会话历史：抽屉（标题 + 关闭 + 搜索 + 状态点/N need you + 底部虚线新建） | **E 稿** | `ChatView` 抽屉 |
| 对话页主体：720px 居中、头部（标题 + chevron、无图标、`⋯` 文本菜单、副行＝工作区·权限） | **v9 稿**（`v9.html` / `v2.css`） | `ChatView` header |
| 过程流：无框无横线、箭头在左、三态默认收起展开 | **v9** | `ProcessTrace` + `TurnStep` |
| dock：输入框上方卡片、Agent 行 / 决策体 | **v9** | `features/chat/RunDock.tsx` |
| 输入框：一个壳（textarea + chip 行 + kbd 提示 + 30px 圆按钮），**与页面不分割** | **v9** | `ChatView` composer |
| 滚动区：内容在输入面前 40px 淡出（`mask-image`），不是用横线切 | **v9** | `.hx-fade-bottom` |
| 决策卡五个问题与文案 | **v7/v9** + PRD 文案 | `features/inbox/DecisionBody.tsx` |

**本轮根据反馈修掉的偏差（第二轮）：**

1. **正文 720 居中**（之前 660）；输入框与 dock 同步。
2. **头部无图标**：去掉了左右图标按钮，右侧改 `⋯` 文本菜单；副行是 `工作区 · 权限`，不重复状态。
3. **助手侧去身份行**：v9 正文里没有 `HubAgent · 时间`，也没有头像；agent 产出用 18px 首字母徽标 + 标题 + 正文（后端就是 `**标题**\n\n正文`）。
4. **用户气泡**：12px 圆角 + 1px 边框 + raised 底，去掉气泡下方的时间戳。
5. **决策体按 v9**：标题 = 动作（`sandbox.relax` → 允许执行一次）、副行 = `N 分钟后过期 · 中等风险`、facts = 为什么/允许后/拒绝后、按钮 = 允许一次/拒绝。为此把 `action / decisionMode / expiresAt` 补进 web 的 `ApprovalRow`（`listApprovals` 本来就返回完整领域对象，只是前端类型太窄）。
6. **输入框**：一个壳（textarea + chip 行 + kbd 提示 + 30px 圆按钮），无 `border-top`、同底色。
7. **滚动区**：`mask-image` 底部 40px 淡出。
8. **待审时过程流收起**；任务/文件 chip 只在完成/失败时出现（对应 v9 的收尾行）。

**性能备注：** 全量 e2e 在本机从 25s 变到 1.5–2 分钟，经 stash 对照确认是环境（Vite 冷启动 / 机器负载）而非本轮改动；`mask-image` 经同用例两次对照（11.6–15.6s vs 13.8–13.9s）不构成回退，保留。

| M | “它自己换 Agent/重试”怎么画 | **已定（v7）**：独立形状 `decided`（所做 + 凭什么 + `why`），不当作第 N 个 `call` |
| N | 审批是流里的卡还是流的一行 | **已定（v7）**：流的一行自己展开（证据 + 两动作 + 中性竖线）。依据：审批必使任务转 `waiting_approval`，与“在跑”不可能共存 |
| O | 折叠的默认态 | **已定（v7）**：running 展开 / waiting 收起 / done 收起；决策体在折叠区外，永不被过程折叠藏住 |
| P | 是否放弃 Warm Ink 换 Graphite | **已定**：放弃。v2–v8 全部画在 Graphite 上；落地含 `tokens.css` + UI-SPEC §2 + 视觉基线重做 |
| Q | 过程行是否显示原始工具名 | **已定（v8）**：不显示。用 `toolLabel()` 已有的效果话术（读取/执行/编辑/搜索/抓取）；产品本来也不存原始工具名 |
| R | Agent 是否使用品牌 logo | **已定（v8）**：暂无官方素材，先首字母徽标 + 运行态反色/脉冲环；18px 槽位可在拿到授权后原样替换 |
| S | “等你”时过程是否默认展开 | **已定（v8 实测）**：不展开。展开 11 行会把批准按钮顶到 1440×1000 的折叠线下 |
| T | 运行中的 Agent 状况放哪 | **已定（v9）**：收进输入框上方可折叠的 dock（v4 那张板的价值）；过程流只留推理与工具，派单/完成不再逐行占位 |
| U | 审批卡用什么形状 | **已定（v9 二次修正）**：dock **本身是一张卡片**（否则与对话、输入框糊在一起），但**内部不再套框/竖线/「你」徽标**；"轮到你"只靠 dock 头琥珀色与实心按钮 |
| V | 过程头与 dock 头是否都写状态 | **已定（v9）**：不。过程头只说“执行过程 · N 步”，状态只出现在 dock 头，避免同屏两处同一句话 |
| W | 多条并发审批怎么呈现 | **已定（v9 二次修正）**：dock 内做队列，一次一条，右上报剩余总数；决定后旧卡左滑出、下一条右滑入（160ms），减动效直接切换。不摊开（会顶出屏幕），不分页（分页要额外的位置信息），不上翻页器（待批总数才是判断依据） |
| X | 任务详情用六段平铺还是竖向证据脊柱 | **已定（P5 渲染评审）**：脊柱。计划 → 需要你 → 执行 → 验收 按时间排，判决在最上面与 diffstat 同屏；决策/事件收进末端「记录」并退一档。六段同权重时读者不知道先看哪里，而“验收过了没”才是第一问题 |
| Y | 失败的运行给几个动作 | **已定（P5）**：两个——`回到对话继续修`（实底）+ `复制失败详情`。重试/取消运行在 V1.7 没有端点，不画假按钮；宁可少一个动作，也不给一个点了没反应的 |
| Z | 任务列表保留「左队列 + 右详情」还是降为深链 | **已定（P5）**：降为深链入口。注意力计数已归 app bar，再摆一条常驻队列等于同一件事数两遍；列表只做「找到那次运行」 |
| AA | 现场/接入 的分段放顶栏还是页面里 | **已定（P7）**：页面里。顶栏 ≤560px 会藏掉分段，那时手机上就无法切换；页面内分段任何宽度都在，且与顶栏页签同一套样式。代价是顶栏只剩页签（不再表达分段），页名对该页退回 `visually-hidden` |
| AB | 验收命令 / 可用 Agent 存哪里 | **已定（P8）**：会话级一列 JSON。它们永远是整份读写，没有按字段查询的需求；拆成多列只会让加一个设置就要一次迁移。坏值由 `parseRunSettings` 退到默认值（旧数据里的 `budget` 字段被忽略） |
| AC | 交付方式是会话设置还是页面动作 | **已定（P8）**：页面动作。PRD §6.12.4 的第一优先级就是「用户单次显式指定」；做成会话默认值反而要回答“哪一次运行用了哪种模式”，而没有交付记录表时无法回答 |
| AD | 间距刻度是「严格 4px」还是「4px + 审核例外」 | **已定（P9）**：4px 网格 + 一组明确列出的例外（2/3/5/7 光学校正、9/14/18/22 来自已批准稿、26 过程流缩进），由 `spacing-scale.test.ts` 看守新增值。理由：为对齐清单去改已评审的视觉稿是本末倒置，而“靠人记例外”又必然漂移——把当前这套固化、让新增值变红，才是可守的 |
| AE | 长历史用分页还是渲染窗口 | **已定（P9）**：两者都要。分页（100 条/页）解决“传输与首屏请求”，渲染窗口（200 回合 + `content-visibility`）解决“已拉下来的长度无上限”。只有分页时 1000 条一次建 1000 个行组件（实测最长任务 ~1s）；只加 `content-visibility` 时首屏仍 18.7s |
| AF | 3D 舞台是否参与像素回归 | **已定（P9）**：不参与。WebGL 场景非确定（光照/时序/GPU 差异），像素比对只会制造假失败；`/agents` 只跑 axe，像素用 `?unsupported=1` 的确定性阻断态 |
| AG | 审批页是复用决策体还是做成只读回看 | **已定（P9）**：待批项复用 `DecisionBody`，已处理项只读。同一个审批对象在浮层、dock、任务详情、审批页必须长得一样，这是同一份语义的四个容器（决策 K）；只读回看只适用于**已经处理完**的那些 |
| AH | 预算控制与 auto-merge 要不要做 | **已定（ADR 0031）**：都不做，并且是**减法**——删字段、删模式、删代码，不是“挂着门禁等以后”。理由：运行时没有用量/费用计量，`maxTokens`/`maxCostUsd` 从来没有被执行过；`auto-merge` 依赖未落地的项目字段，且与「人确认」的产品前提冲突 |
| AI | 约束护栏是否也跟着删 | **已定（ADR 0031）**：不。墙钟、回合动作数、token 估算上限保留为**不可配置的常量**——它们防的是进程挂死，不是费用。把“不需要成本预算”误解为“不需要超时”会让 daemon 卡在一次不返回的回合里 |
